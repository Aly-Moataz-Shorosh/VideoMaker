# Script → generated video (style 27 / avatar mode) with the reach method

For «اعملي سكريبت وولد الفيديو» — long YouTube (style 27 ai-world-explainer) or a vertical short with his AI twin.
Production rules live in video-maker: `docs/33` (avatar mode, paid services: say the credit cost before EVERY generation, shortest
test first, never auto-regenerate), `docs/36` (style 27 recipe + pipeline v11), `docs/37` (his twin, voice, S4g studio, IDs),
`docs/34` (hybrid reel). This file decides WHAT the script is so the generation money goes into a video built for reach.

Homus: idea 40% + script 40% of the result, and ~75% of the work happens BEFORE production. With AI generation this is even truer:
every re-voice and re-render costs credits and a version. So the script is locked with Aly BEFORE any credit is spent.

## Order of work
1. **Research (cheap):** what already performs on this topic in Arabic and abroad (reference bank: 10-20 strong videos, why each worked,
   the gap nobody fills). His sourcing rules for every fact (exact sentence + link + marked screenshot).
2. **Idea card** (`scripting.md` Step 0): type A/B/C, format, series, one-sentence idea, promise, target signal, test variable.
   Long AI explainers are B; their shorts are A; one C short sells the long one.
3. **Packaging** (long video): 3 titles + thumbnail (Higgsfield method, `docs/37`) — the first 5 s must pay them off.
4. **Hooks**: 3 versions on the ladder (bad/better/best), pause test, Aly picks. For style 27 the hook's FIRST FRAME is a visual
   (the strongest generated result / a glitch / a real proof), NOT the twin saying hello — visual > text > verbal. The twin comes in
   after the promise lands.
5. **Script per SENTENCE** (style 27 = one explaining visual per sentence): for each sentence write `line | visual on its word | technique`
   (micro-hook, proof, one-up, contrast, signpost…). Twin lines: vary sentence length on purpose (the TTS/twin voice flattens rhythm),
   short punchy lines at re-hooks, no line that repeats an earlier one (REDUNDANCY), concept before name (delayed labeling), and
   explain-before-result for every example («تعالوا نسمع/نشوف النتيجة» then the result alone).
6. **Retention map** for the whole video: re-hook every 60-90 s, mini resets ≤ 3, one open loop from the hook closed near the end,
   signposting = TreeMap separators + breadcrumb, escalation toward the biggest payoff, one NEW promise before the last third.
7. **CTA + clean exit**: one CTA tied to the next video/series or the keyword, his real photo «ده أنا» (style 27 ending), no long goodbye.
8. **Pre-post score /50** + the list of shorts to cut from it (`shorts-from-long.md`) — written now, not after the render.
9. **Cost card**: credits per service for the locked script (twin minutes, voice, B-roll, song), shortest test first → Aly says «نفذ».
10. Generate + build with the docs/36 pipeline; review notes law and overlap law as always.

## Vertical AI short (twin, ≤ 60-90 s)
Same card, but A-type by default: first frame = the most surprising generated/real visual, ≤ 6 words of text, the twin's first line
is the promise (not a greeting), a change every 1.5-3 s, micro-hook every 10-15 s, loop ending, a specific-comment CTA. One short =
one promise. If several shorts are planned, plan them as a SERIES (one format, 5+ episodes) so each new one costs less to script and the
audience binges.
